## Migration

`python intercom_to_mintlify.py --migrate` is the full run. It reads
`navigation.json`, fetches every article, and writes each page into the
directory of the group whose `collections` list claims it. `docs.json` is not
written here - `build_nav.py` runs at the end and rebuilds it from disk.

Only GET endpoints are used, and no write endpoint is ever called:

```
GET /help_center/collections   the Product / Section tree used for grouping
GET /articles                  every article summary, 150 per page
GET /articles/{id}             the full body
```

Per-article JSON is cached under `intercom_export/articles/` and reused when
`updated_at` matches, so a re-run only fetches what changed. Useful flags:
`--limit N` (smoke test), `--dry-run`, `--refresh`, `--no-nav`.

Rules the run applies:

- **Page shape mirrors oloid.help.** Headings keep their own text and their own
  relative depth; nothing is renamed to a template section and nothing is
  promoted. The one exception is the no-H1 rule below.
- **Articles with an empty body are skipped** and listed in the report, rather
  than written as blank pages.
- **A group's `overview.mdx` placeholder is deleted** once real articles land in
  it. Groups still empty keep theirs so the navigation renders.
- **Unmapped collections are reported, never guessed.** If Intercom grows a
  collection that no group claims, its articles are written to Drafts >
  Unassigned > Collection not in navigation (the group with
  `"catch_unmapped": true`) and listed under UNMAPPED - add the collection to
  a group in `navigation.json` and re-run to move them.
- **Title rules place what collections can't.** A group's `match` holds title
  regexes (`titles`) tried before the collection mapping, against articles from
  `_Unassigned` plus the collections in `from` (`"*"` = any). First match wins,
  children before their parent, in `navigation.json` order. This is how Zebra,
  Linux, Citrix, the Vaults, Time Clock and most of `_Unassigned` find a home;
  every title placement is listed in the report under PLACED BY TITLE.
- **Stale pages are deleted.** A full run removes every page carrying the
  "Generated by intercom_to_mintlify.py" marker that it did not write this time,
  so moving a group moves its pages. `--limit` and `--dry-run` never delete.
  Hand-written pages have no marker and are never touched.
- **Polish runs last** (`--polish` runs it alone, no token): screenshots get a
  line of their own with a blank line either side, small images (icons and
  buttons, by pixel size, or any image mid-sentence) become
  `<img className="oloid-icon" noZoom />`, generic alt text is replaced by the
  step it illustrates, `sidebarTitle` drops the product prefix without "...",
  and every `oloid.help/en/articles/<id>` link is pointed at the page migrated
  from `<id>`. Links to articles that were not migrated keep their URL and are
  counted in the report.
- **Tables are Markdown tables.** Intercom has no header cells, so the first
  row is the header (bold-only header cells are unwrapped). A cell is one
  line: its paragraphs and line breaks become `<br />`, its lists
  `• item` / `1. item`, its images stay inline and a video becomes a link.
  Columns empty in every row are dropped. The Keywords block at the end of
  an article stops at the next heading, so a Document History table after
  it is kept.
- **SEO fields are hidden in the frontmatter.** The polish (so every
  `--migrate` and `--polish`) rewrites each generated page's frontmatter with
  `keywords`, `canonical`, `og:title`/`og:description`,
  `twitter:title`/`twitter:description`, `boost` (0.7 for Videos, 0.5 for the
  Drafts tab) and the custom fields `section`, `product`, `subsection`. None
  of it renders; Mintlify emits it as meta tags and indexes `keywords` in
  search. Intercom's own keywords come first; the ones below the
  `# derived by intercom_to_mintlify.py` comment (short title, section path,
  H2/H3 headings, synonyms from `SYNONYMS`) are rebuilt on every run, 15 at
  most. Descriptions are Intercom's; a page with none gets its first
  sentence. `canonical` uses `--docs-url`: after moving to a custom domain run
  `--polish --docs-url https://<domain>`.
- `python intercom_to_mintlify.py --plan` shows where every article in
  `output/_all_articles.csv` will land, and which were placed by title, without
  a token. Run it after editing `navigation.json`.
- **Drafts go under `drafts/`.** An article with `state: draft` is written to
  `drafts/<its group's path>` instead of the group itself, and appears in the
  Drafts tab.
- **Excluded collections are kept out of the main navigation, not dropped.**
  `navigation.json`'s `excluded_collections` (M-Tag, Oloid App, What is Oloid?,
  Glossary, Platform Starter) are fetched and written to Drafts > Excluded
  (`drafts/excluded/<collection>/`, one group each), never placed by a title
  rule, and tagged "excluded" in the report and the manifest. To bring one
  into the main navigation, move it from the Excluded menu and
  `excluded_collections` into a group in one of the main tabs.
- **The manifest.** Every run writes `intercom_manifest.json` (mint-ignored):
  one record per article Intercom returned, with `oloid_help_url` (old),
  `mintlify_url` (new, on `--docs-url`, default the mintlify.app domain),
  `navigation` ("Platforms & Solutions > Windows > Windows Login > ..."),
  `file`, `status`, `placed_by` and the Intercom collection, plus a list of
  sections with their article ids. Each record has a `category` - `added`
  (main navigation), `excluded`, `unassigned` (no collection in Intercom) or
  `unmapped` - and `tags` (the category, `published`/`draft`,
  `placed-by-title`, `video`, `not-written`, `has-issues`). `lists` groups
  every article by tag, so `lists.excluded` or `lists.unassigned` is the full
  list of each.
- **Every problem is recorded, per article.** Each record has `issues`, a list
  of `{type, detail}`: failed fetches, image downloads that failed (e.g.
  `HTTP Error 404`, with the URL - the page keeps Intercom's expiring URL),
  oversized images, conversion errors, failed writes, and what `lint_page`
  still finds on the finished page after the polish: remote images, links to
  articles that were not migrated, raw HTML, unclosed `<Note>`/`<Frame>`/code
  blocks, an H1 in the body, glued screenshots, generic alt text, dead
  `#h_` anchors, empty link text, leftover `&nbsp;`. `counts.articles_by_issue`
  totals them, `lists.has-issues` lists the affected pages with their issues,
  and `$issues` in the file explains each type. One article failing to
  convert is recorded and skipped; it no longer stops the run. `--dry-run`
  downloads no images, so it cannot see image failures.
  Unassigned articles, published or not, live in `drafts/unassigned/`.
- **Video-only articles go to the nearest Videos group.** A page that is a
  video embed plus at most 40 words (`VIDEO_ONLY_WORDS`) is written to the
  closest group with slug `videos` at or above its home, e.g. Windows Login V2
  -> Windows > Videos, Tenant Admin Portal -> Tenant Admin Portal > Videos.
  Articles that embed a video among real steps stay where they are, and a
  group with `"keep_videos": true` (Product Videos) is never emptied of them.

## Document template

The template below is the *older* enforced shape, still applied by
`python intercom_to_mintlify.py --reformat` (no Intercom token needed). The
`--migrate` run above does not use it: it mirrors oloid.help instead.

```
---
title:        full article title        <- the page's ONLY H1
sidebarTitle: short form for the nav
description:  one sentence
icon:         file-lines
keywords:     [...]                     <- feeds search, renders nothing
---

## Introduction            required
## Prerequisites           required, bullet list
## Steps to <do the task>  required, numbered procedure
###   sub-procedure
####    sub-sub-procedure
## Additional Information  optional
## Related Articles        optional
```

Rules the script applies, and that hand-edits must keep:

- **Never write an H1 in the body.** The frontmatter `title` is the page's only
  H1. An `# Heading` renders as a second 32px title, which is what made pages
  look oversized. Body sections start at `##`.
- **Indent list continuations to the content column**, not a flat two spaces:
  3 spaces under `1. `, 2 under `- `, 4 under `10. `. A step's screenshot, its
  note and its sub-steps all share that column. This is the alignment rule.
- **Notes are callouts.** `**Note:**` becomes `<Note>`; Important/Caution/
  Warning become `<Warning>`; Tip becomes `<Tip>`. Indent the callout to the
  column of the step it belongs to.
- **Screenshots are plain markdown** (`![alt](/images/...)`), not `<Frame>`.
  Frame is a block component and cannot sit inside a step. `style.css` gives
  images the rounded border instead. `<Frame>` is still used for videos.
- **Keywords live in frontmatter only.** Intercom's trailing one-row pipe table
  renders as a malformed box; the script lifts it into `keywords:`.
- **No Intercom `#h_xxxx` anchors** - they 404 in Mintlify. The script rewrites
  them to real heading slugs, or drops the link if it cannot resolve one.
- Section headings are canonical: "Prerequisites" (not "Prerequisite"),
  "Related Articles", "Additional Information", trailing "Tab" capitalised.

Missing required sections are reported, never invented - add them by hand.

## Navigation

`docs.json` and `index.mdx` are **generated**. `navigation.json` is the source of
truth: the tab / menu / group tree, plus the Intercom collections
(`Product :: Collection`) whose articles belong in each group.

The tree has these tabs:

- **Platforms & Solutions** (`platforms/`)
- **Integrations** (`integrations/`)
- **OLOID Platform** (`platform/`)
- **Help & Reference** (`reference/`)
- **More Resources** (`more/`) - the home for everything the new tree has no
  place for yet (Workflow, SSO & MFA, API guides, release notes, unqualified
  Passwordless Authenticator collections).
- **Drafts**, mirrored automatically (below).

There is no Home tab. `/` still serves `index.mdx` (see below), which sits in
no tab.

A **Getting Started** tab of hand-written setup guides is planned but not
built: the tree, the page shape and a finished reference page are in
`plans/getting-started.md` (mint-ignored).

Each main tab carries `"group_menu": true`: its top-level groups (Windows,
iOS / iPadOS, Tenant Admin Portal, ...) become a dropdown menu at the top of
the sidebar, and the sidebar shows only the section picked there. A menu item
holds groups only, so a section's own pages sit in a group of the same name.
This changes `docs.json` only - directories, placement and the manifest's
`navigation` path are the same. Remove the key from a tab to put its sections
back as stacked sidebar groups.

Groups nest (Windows > Windows Login > Windows Login V1); each nested group is a
directory inside its parent's. Within a group the sidebar shows sub-groups,
then its own pages, then its Videos group.

```
python build_nav.py --tree      # report only: the tree, page counts, unmapped groups
python build_nav.py             # write docs.json, index.mdx and placeholders
```

- A group's pages are whatever `.mdx` files sit in its directory, so migrated
  content wires itself into the nav with no config. A declared leaf group with
  no pages yet (Linux & Thin Clients, Workspace ONE, EPCS) gets an
  `overview.mdx` placeholder so it still shows; it is removed once other pages
  land beside it. Videos groups never get one - they appear once they hold
  videos.
- `index.mdx` is a generated card index of every tab, with article counts. It
  is the page at `/` and belongs to no tab. Edit the header text in
  `LANDING_HEADER` in `build_nav.py`.
- The **Drafts** tab carries `"mirror_drafts": true`. `build_nav.py` fills it
  automatically with one menu per visible tab, holding that tab's groups,
  reading from `drafts/<tab>/<group>/`.
  Groups with no drafts are left out. Only its extra menus (Unassigned,
  Excluded) are declared by hand. `drafts/` must stay out of `.mintignore` - the starter kit
  ignored it, which hid every draft page from the build.
- The navbar lives in `navigation.json` too. The Support link is parked in
  `navbar.hidden_links`; move it back into `links` to restore it.
- Hand edits to `docs.json` or `index.mdx` are lost on the next run. Edit
  `navigation.json`.


## Ask Oloid assistant

`ask-oloid.js` / `ask-oloid.css` are the topbar button and chat sidebar. They
POST the conversation to `CONFIG.endpoint`, a Cloudflare Worker in
`ask-oloid-worker/` that holds the Claude API key and answers from the docs.

- **The key is a Worker secret, nowhere else.** Never put it in
  `ask-oloid.js`, `docs.json`, `wrangler.toml` or a committed file: every
  `.js` in this repo is shipped to visitors. `ask-oloid-worker/` and
  `.wrangler/` are in `.mintignore` for the same reason.
- **Knowledge base.** `build_index.py` turns every published page (not
  `drafts/`, not `excluded/`) into sections plus a BM25 index. Wrangler runs it
  on each `dev`/`deploy`, so redeploying the Worker after a docs change is
  what refreshes the assistant.
- **Behaviour lives in `ask-oloid-worker/src/system-prompt.txt`.** It answers
  only Oloid / docs questions (anything else gets a one-line polite redirect),
  uses the docs first, falls back to web search / fetch (any site, at most 3
  of each per answer) only for Oloid-related gaps, and ends with a
  "Related articles" list. Edit the file, then `npx wrangler deploy`.
  Links to docs pages that don't exist are unlinked by the Worker.
- **Abuse limits.** Only origins in `ALLOWED_ORIGINS` are served, 10 questions
  a minute per IP, 10 turns of history at 2,000 characters each. Error
  replies are generic; upstream errors are logged as a status code only.

```
cd ask-oloid-worker
npm install
npx wrangler login
npx wrangler secret put ANTHROPIC_API_KEY   # paste the key at the hidden prompt only
npx wrangler deploy                         # prints the https://...workers.dev URL
```

Then set `CONFIG.endpoint` in `ask-oloid.js` to that URL and add the docs
domain to `ALLOWED_ORIGINS` in `wrangler.toml`. For local testing, put the key
in `ask-oloid-worker/.dev.vars` (git- and mint-ignored) and run
`npx wrangler dev` alongside `mint dev`.

## Typography

Page *structure* follows oloid.help exactly (verified: all 16 headings match
1:1 in level and order, 31 images vs 31). The *size* is deliberately one notch
below it, because the help-centre scale reads large on a docs site that also
has a sidebar:

```
                oloid.help      here
    body          16px          15px
    h1 (title)    32px          27px
    h2 section    24px          19px
    h3            20px        16.5px
    h4            18px          15px
    line-height   1.53          1.60
```

`docs.json` cannot change any of this: `styling` carries only `eyebrows` and
`codeblocks`, and `fonts` only takes family/weight - there is no size or
density key. The topbar search/assistant width is one of them
(`--oloid-search-width`). All sizes are CSS variables at the top of the `STYLE_CSS`
constant in `intercom_to_mintlify.py`, so making it smaller again is one block
to edit. Do not edit `style.css` directly; the script overwrites it.

The `luma` theme is kept because it already has the narrowest content column
of the available themes (max-w-174, about 696px, against mint's 864px and
aspen's 1152px). Switching theme changes styling, not size.

`docs.json` also has every starter-kit link stripped - anchors, navbar links
and social accounts that still pointed at mintlify.com - and the per-page
contextual toolbar trimmed from 8 options to 4. The script only removes links
pointing at mintlify.com, so real Oloid URLs are left alone once added.
