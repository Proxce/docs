## Introduction

Okta Single Sign-On (SSO) enables secure authentication for users accessing the Oloid Portal and Oloid Applications. To complete the integration, admin first configure policies and applications in the Okta Admin Console and then share the required parameters with Oloid. This setup ensures that authentication requests are validated through Okta using the appropriate authorization policies and client configurations.

## Prerequisite

You must have Admin access to the Okta Admin Console.

## Steps to Configure Okta SSO login in the Okta Admin Console for Oloid Portal

**Step 1:** Configure Client Application for Oloid Portal and Oloid Application

**Step 2:**  Create and Configure Default Policy in an authorization server in the Okta Admin Console

### Steps to Create and Configure Client Application for Oloid Portal and Oloid Application

1. In the Okta Admin Console, go to **Applications > Applications > Create App Integration.**
   ![Okta Settings for Oloid SSO - screenshot 1](/images/intercom/8158793/image-3c6d5df2.png)
   The Create a new app integration pop-up box is displayed.
2. Do the following:
   1. Select **OIDC - OpenID Connect** as the **Sign-in method.**
   2. Select **Single-Page Application** as **Application type**.
   3. Click **Next**.
      ![Okta Settings for Oloid SSO - screenshot 2](/images/intercom/8158793/ce867c9d-a84c-49d4-aa33-0bebe777231c-62f26a5c.png)
      The New Single-Page App Integration page is displayed.
3. Enter a name for the application in the **App integration name** field.
   ![Okta Settings for Oloid SSO - screenshot 3](/images/intercom/8158793/d237ee9a-fe29-40ab-8e6b-730e371c0e70-3a1e92eb.png)
4. Select **Authorization Code** as **Grant type** (If not already selected).
   ![Okta Settings for Oloid SSO - screenshot 4](/images/intercom/8158793/3a3ef1a1-4e39-4661-ab7e-d01bae774521-c9b810f2.png)
5. Add the redirected URLs to **Sign-in redirect URIs** field.
   ![Okta Settings for Oloid SSO - screenshot 5](/images/intercom/8158793/b74def0d-c8db-4404-ac6f-8ffd95d66dde-809f8f2a.png)
   To copy the redirected URL, go to **Oloid Portal** > **Tenant Settings** > **Security** > **OKTA** and copy the following **Redirect URLs**.
   ![Okta Settings for Oloid SSO - screenshot 6](/images/intercom/8158793/cb931325-a8e3-4d30-abb7-11c3aaec5ff2-405ac965.png)
6. Select **Allow everyone in your organization to access** under **Assignments**.
   ![Okta Settings for Oloid SSO - screenshot 7](/images/intercom/8158793/7505129a-87dd-470c-b0a0-333c82aee6b1-ab325c22.png)
7. Click **Save**.
   The newly created application page is displayed.
8. Go to **General** tab, share the **ClientID** of the new app with Oloid.
   ![Okta Settings for Oloid SSO - screenshot 8](/images/intercom/8158793/image-b3225cfd.png)
   You can use the client ID in the Web Client ID field. You can find the web client ID field in the Oloid portal under **User Profile > Tenant Settings > Security > Okta**.
   ![Okta Settings for Oloid SSO - screenshot 9](/images/intercom/8158793/2cb72060-3f02-44bd-b7cb-4e6acb2c2160-ae31259d.png)
9. Go to **User Profile** icon and share the domain ID with Oloid.
   ![Okta Settings for Oloid SSO - screenshot 10](/images/intercom/8158793/image-1bdd2574.png)
   You can use the Domain ID in the Domain field. You can find the Domain ID field in the Oloid portal under **User Profile > Tenant Settings > Security > Okta**.
   ![Okta Settings for Oloid SSO - screenshot 11](/images/intercom/8158793/fa02f443-ca4d-47c7-a0a9-fab4cf9c05ab-b687cba3.png)
10. On the left panel, select **Security** > **API**.
    ![Okta Settings for Oloid SSO - screenshot 12](/images/intercom/8158793/4da19fb0-08a4-48c8-8c52-e1cd619c4801-bd5afb31.png)
11. Under **Authorization Server** tab, share the **Default Issuer URL** with Oloid Admin.
    ![Okta Settings for Oloid SSO - screenshot 13](/images/intercom/8158793/7c67b168-aa74-4604-8127-4e873d12552e-c3d8ec81.png)
    You can use the Default Issuer URL in the Web Client ID field. You can find the web client ID field in the Oloid portal under **User Profile > Tenant Settings > Security > Okta**.
    ![Okta Settings for Oloid SSO - screenshot 14](/images/intercom/8158793/34da6e62-a4a6-459e-9b1b-48af68ccc3bd-c4f74f8f.png)

### Steps to Create Default Policy

1. On the left menu panel, go to **Security** > **API** > **Authorization Servers** tab > Select **default**.
   ![Okta Settings for Oloid SSO - screenshot 15](/images/intercom/8158793/fda85d90-a162-4cab-aed0-8deb53a96fdd-1a3a4b6f.png)
2. On the default page, select **Access Policies** > **Add Policy**.
   ![Okta Settings for Oloid SSO - screenshot 16](/images/intercom/8158793/26324a9e-7bd0-443d-a056-2e1ecdd5f8b2-1c1c5284.png)
   The Add Policy pop-up box is displayed.
3. On the pop-up box, do the following:
   1. Enter **Name** and **Description** in respective fields.
   2. Select **The following clients** as Assign toand then enter the preferred application name in the respective field.

      <Note>
        **Note:** Assign the policy only to the specific client application that you created in the first step.
      </Note>

   3. Click **Create Policy**.
      ![Okta Settings for Oloid SSO - screenshot 17](/images/intercom/8158793/image-89f347ac.png)
      The access policy is created successfully.
      ![Okta Settings for Oloid SSO - screenshot 18](/images/intercom/8158793/2114cdf0-0748-40db-8258-13c8448f741f-d3478092.png)
4. Next, select **Add rule**.
   ![Okta Settings for Oloid SSO - screenshot 19](/images/intercom/8158793/300853e2-5290-46ec-98a0-49718d44b6eb-31875723.png)
5. On the **Add Rule** pop-up box, configure the details as required.
   ![Okta Settings for Oloid SSO - screenshot 20](/images/intercom/8158793/image-8f1cd36b.png)
6. Click **Create rule**.
   ![Okta Settings for Oloid SSO - screenshot 21](/images/intercom/8158793/image-8f4f9d59.png)
   The rule is added successfully.
